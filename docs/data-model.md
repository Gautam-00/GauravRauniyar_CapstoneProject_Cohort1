# Data Model

Each microservice logically owns a separate database. No cross-database queries are permitted.

## 1. Catalog Service (`cake_catalog_db`)

### Collection: `cakes`
- `_id`: ObjectId
- `name`: String (Required) - e.g., "Chocolate Truffle"
- `description`: String (Optional)
- `category`: String (Required) - e.g., "Chocolate", "Fruit"
- `price`: Number (Required)
- `available`: Boolean (Required, default: true)
- `imageUrl`: String (Required) - Path to static frontend image, e.g., `/images/chocolate-truffle.jpg`

## 2. Order Service (`order_db`)

*Anonymous Customer/Client Identification: The application does not implement authentication. An anonymous customer/client UUID is generated by the frontend and persisted in localStorage. The UUID is sent through the X-Customer-Id header so that the Order and Notification services can associate application data with the same client.*

### Collection: `baskets`
- `_id`: ObjectId
- `customerId`: String (Required) - Unique ID from the frontend
- `items`: Array of Objects
  - `cakeId`: String
  - `name`: String (Denormalized from Catalog at add time)
  - `price`: Number (Snapshotted from Catalog at add time. Follows MVP Price Snapshot Assumption: basket retains the price even if catalog changes.)
  - `quantity`: Number

### Collection: `orders`
- `_id`: ObjectId
- `customerId`: String (Required)
- `items`: Array (Same structure as Basket items)
- `totalAmount`: Number (Required)
- `status`: String (Default: "COMPLETED")
- `createdAt`: Date

## 3. Rating Service (`rating_db`)

### Collection: `ratings`
- `_id`: ObjectId
- `cakeId`: String (Required)
- `rating`: Number (Required, 1-5)
- `comment`: String (Optional)
- `createdAt`: Date

## 4. Notification Service (`notification_db`)

### Collection: `notifications`
- `_id`: ObjectId
- `customerId`: String (Required)
- `orderId`: String (Required)
- `message`: String (Required)
- `read`: Boolean (Default: false)
- `createdAt`: Date

## Seeding Strategy
- **Mechanism**: The Catalog Service will check `db.cakes.countDocuments()` on startup. If `0`, it inserts a predefined array of demo cakes.
- **Idempotency**: This prevents duplicate records across container restarts. 
- **Scope**: Only the Catalog needs seeding for the MVP. Orders and notifications will be generated via user flow.
