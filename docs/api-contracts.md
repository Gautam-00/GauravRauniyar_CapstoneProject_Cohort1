# API Contracts

## Express Gateway Routing
The Express Gateway serves as a reverse proxy on port 3000. It routes requests based on path prefixes:
- `http://localhost:3000/api/catalog/*` -> Cake Catalog Service (e.g., port 3001)
- `http://localhost:3000/api/orders/*` -> Order Service (e.g., port 3002)
- `http://localhost:3000/api/ratings/*` -> Rating Service (e.g., port 3003)
- `http://localhost:3000/api/notifications/*` -> Notification Service (e.g., port 3004)

**Anonymous Customer/Client Identification**:
The application does not implement authentication. An anonymous customer/client UUID is generated by the frontend and persisted in localStorage. The UUID is sent through the X-Customer-Id header so that the Order and Notification services can associate application data with the same client.

## 1. Catalog Service APIs
### `GET /cakes`
- **Purpose**: List and filter cakes.
- **Query Params**: `name` (string), `category` (string), `minPrice` (number), `maxPrice` (number)
- **Response Example**:
  ```json
  [
    {
      "_id": "6a7979c5cfcee900e592f0fd",
      "name": "Classic Chocolate Truffle",
      "category": "Chocolate",
      "price": 35,
      "available": true,
      "imageUrl": "/images/chocolate-truffle.jpg"
    }
  ]
  ```

### `GET /cakes/:id`
- **Purpose**: Get cake details.
- **Response**: `200 OK` Cake object.
- **Error Examples**:
  - `400 Bad Request`: `{"message": "Invalid Cake ID format"}` (If `:id` is not a valid ObjectId)
  - `404 Not Found`: `{"message": "Cake not found"}` (If valid ID format but does not exist)

## 2. Order Service APIs
### `GET /basket`
- **Purpose**: Retrieve the user's basket. (Uses `X-Customer-Id`).
- **Response**: `200 OK` Basket object. Returns empty basket structure if none exists.

### `POST /basket/items`
- **Purpose**: Add a cake to the basket.
- **Body**: `{ "cakeId": "string", "quantity": number }`
- **Logic**: Service makes a direct internal synchronous REST call to `GET /cakes/:cakeId` on the Catalog Service (bypassing Gateway) to validate existence, availability, and fetch the trusted name and price. If valid, the price and name are stored as a snapshot in the basket item. If the catalog price changes later, the basket item continues using its snapshotted price (MVP Price Snapshot Assumption).
- **Response**: `200 OK` Updated basket. Error `404` if cake not found in Catalog.

### `PUT /basket/items/:cakeId`
- **Purpose**: Update item quantity.
- **Body**: `{ "quantity": number }`
- **Response**: `200 OK` Updated basket.

### `DELETE /basket/items/:cakeId`
- **Purpose**: Remove item from basket.
- **Response**: `200 OK` Updated basket.

### `POST /checkout`
- **Purpose**: Convert current basket to an order.
- **Response**: `201 Created` Order object. Error `400` if basket is empty.

---

## 3. Rating Service APIs
### `POST /ratings`
- **Purpose**: Submit a new rating.
- **Body**: `{ "cakeId": "string", "rating": 5, "comment": "string" }`
- **Response**: `201 Created` Rating object.

### `GET /ratings/average/:cakeId`
- **Purpose**: Get the average rating for a specific cake.
- **Response**: `200 OK` `{ "cakeId": "string", "averageRating": 4.5, "totalRatings": 12 }`

---

## 4. Notification Service APIs
### `GET /notifications`
- **Purpose**: Retrieve notifications for the user (Uses `X-Customer-Id`).
- **Response**: `200 OK` Array of notification objects.
